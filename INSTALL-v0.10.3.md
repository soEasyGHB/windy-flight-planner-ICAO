# Windy Flight Route Analyzer v0.10.3 — восстановление открытия плагина

## Почему v0.10.2 перестал открываться

В `src/plugin.svelte` инициализация таблицы изобар выполнялась через `WINDY_PRESSURES`, которая не объявлена после перехода на Open-Meteo. При открытии Svelte-компонент падал с `ReferenceError: WINDY_PRESSURES is not defined`. В v0.10.3 используется импортированный массив `PRESSURES` из `src/weather.ts`.

Также ошибки установки слоя карты Windy теперь перехватываются: если Windy не даёт выбрать слой/модель, это не блокирует окно плагина. Добавлен тест `npm run check:startup`, который исполняет инициализацию скрипта компонента с тестовым окружением и проверяет `onopen`. Негативный тест специально возвращает старую ошибку и подтверждает, что она выявляется.

## Установка через GitHub Codespaces

Загрузите `Windy-Flight-Route-Analyzer-FULL-v0.10.3.zip` в **корень репозитория**. В терминале Codespaces выполните следующие команды целиком:

```bash
unzip -o Windy-Flight-Route-Analyzer-FULL-v0.10.3.zip
rm -f src/windyWeather.ts api/windy-forecast.js tests/test_windy_proxy_v010.mjs
npm install --no-audit --no-fund
npm run test:release
```

`npm run test:release` обязан завершиться **без ошибок**: он проверяет файлы, локальные импорты и экспорты, TypeScript, старые тесты, новый тест запуска Svelte, **настоящую компиляцию Rollup** и комплектность `dist`.

**Если тесты или сборка не прошли, не публикуйте.** Пришлите первую ошибку из терминала или красного задания GitHub Actions.

Только после успешного теста:

```bash
git add -A -- . ':(exclude)*.zip' ':(exclude)*.sha256'
git status --short
git commit -m "Fix Windy plugin opening v0.10.3"
git push origin main
```

До коммита посмотрите `git status --short`: исключите случайно добавленные личные файлы/ключи. Если ветка у вас не `main`, используйте свою рабочую ветку вместо `main`.

Откройте **GitHub → Actions → publish-plugin → Run workflow → main**, убедитесь, что сборка и публикация завершились успешно. После публикации **перезагрузите страницу Windy с очисткой кеша**, закройте и снова откройте плагин. Если старая версия всё ещё открывается, подождать не требуется: проверьте в Actions, что опубликована именно версия `0.10.3`, затем переоткройте плагин.

## Настройка API

Данные таблицы поступают **напрямую из Open-Meteo NOAA GFS**. Для них не требуется ни Windy Point Forecast API, ни Vercel, ни другой ключ. В GitHub Actions для *публикации плагина* может требоваться секрет **`WINDY_API_KEY`**. Это отдельный ключ, и его не надо вводить в интерфейс плагина.

## Если после публикации окно всё ещё не открывается

1. Проверьте **GitHub → Actions → publish-plugin**: сборка и upload должны быть зелёными.
2. На desktop откройте Windy, нажмите `F12` → **Console** и найдите первую красную ошибку с `plugin` или `flight-route-analyzer`. Пришлите её полностью и ссылку на страницу плагина.
3. На iPad откройте Windy в Safari, обновите страницу, затем попробуйте снова открыть плагин. Для углублённой диагностики понадобится журнал браузера или лог публикации GitHub Actions.

Примечание: здесь проверены исходники и эмуляция запуска скрипта. Прямой доступ к вашему **приватному установленному экземпляру Windy** отсутствует, поэтому реальное открытие в браузере и успешная сборка, требующая npm-пакетов, должны быть подтверждены в Codespaces/Actions.

**Авиационное ограничение:** приложение — демонстрационный метеоанализ, не эксплуатационный источник расчёта OFP, NOTAM, SIGWX, допустимых эшелонов или навигационной информации.
