# Быстрая инструкция — X-Plane и Windy на iPad

## Если тебе просто нужно нарисовать полёт сегодня

1. Скачай/найди навигационные данные X-Plane 11/12 в архиве твоего поставщика. Убедись, что имеешь право использовать их в стороннем приложении.
2. В приложении «Файлы» распакуй ZIP (один тап по ZIP). Нужны ровно три файла **из одного и того же набора и AIRAC**: `earth_fix.dat`, `earth_nav.dat`, `earth_awy.dat`. Папки CIFP, airspaces и прочие для текущей версии не требуются.
3. Открой Windy с установленным нашим плагином. Прокрути до раздела **«Навигационная база X-Plane 11/12»**.
4. Нажми **«Добавить три файла X-Plane»**, выдели все три в окне «Файлы», затем **«Импортировать X-Plane в Windy»**.
5. Увидишь сообщение с AIRAC, числом точек и сегментов. Вставь маршрут, нажми **«Построить маршрут»** и выбери нужные погодные слои.
6. Если точки не найдены или воздушная трасса не развернулась, смотри предупреждения в панели. **Не считай соединённую прямую точной геометрией ATS-трассы.**

Это работает без GitHub для данных. После перезапуска вкладки выбирай файлы заново.

## Если хочешь хранить общую базу в GitHub

Только для данных, чья лицензия **разрешает публичное размещение**.

1. На GitHub переведи репозиторий с конвертером в **Public** *только после проверки содержимого*. Можно создать отдельный публичный репозиторий только для разрешённой навигационной базы. Персональные ключи не должны быть в файлах.
2. В `navdata-input/` нажми **Add file → Upload files**, выбери три `.dat` и нажми **Commit changes**.
3. Во вкладке **Actions** дождись успешного `build-navdata`. Если нет прав на автоматический commit, включи **Settings → Actions → General → Read and write permissions** для workflow. Если файлы не загружались, можно вручную выбрать `build-navdata → Run workflow`.
4. Убедись, что в `public/navdata/manifest.json` поле `status` = `ready`, а `airac_cycle` совпадает с загруженным циклом.
5. В Windy один раз вставь `https://github.com/USERNAME/REPO` в поле «Ссылка на публичный GitHub-репозиторий» и нажми **«Обновить базу из GitHub»**. Адрес запоминается браузером; при очередном запуске плагин попробует получить эту базу сам.

Для каждого следующего обновления данных повторяй только **шаги 2–3**. Сам плагин повторно публиковать не нужно.

## Что выбрать?

- **Есть действующая персональная навигационная подписка:** не загружай её файлы в публичный GitHub. Используй прямой локальный импорт в Windy, если лицензия это допускает.
- **Есть законно открытая база:** обновляй её в GitHub — удобнее всего для постоянной работы на iPad.

**Ограничение:** это визуализация погодных условий вдоль предполагаемого маршрута. Текущий код не проверяет применимость ATS-сегментов по направлениям, эшелонам, AIP/NOTAM и действительности AIRAC; не заменяет действующий OFP, метеобрифинг или навигационную базу авиакомпании.
