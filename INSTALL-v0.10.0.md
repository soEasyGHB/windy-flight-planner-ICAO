# Windy Flight Route Analyzer v0.10.0 — установка GitHub + Vercel + Windy

## Что изменилось

1. На главной странице **пять** карточек: ввод маршрута, дата/время UTC, слой погоды, **«Наш планировщик полёта»**, ниже штатный **«Планировщик полёта» Windy**.
2. Ручное поле FL удалено. Для FL330–390 вычисляются независимые метеорологические рекомендации для **чётных** (FL340, 360, 380) и **нечётных** (FL330, 350, 370, 390) эшелонов. Критерий: максимум взвешенной по длине участка продольной составляющей попутного ветра; если все значения отрицательны, минимум встречного. Показаны две ненавязчивые голубые линии и подписи внизу.
3. ISA-изолинии пунктирные, с подписями `ISA +5°`, `ISA -15°` и т. п. (там, где есть пересечение с данными модели). Цвет фона приглушён.
4. Стрелки попутного/встречного ветра приглушены.
5. Тропопауза строится в отдельной узкой полосе над FL-графиком, с собственной шкалой FL — поэтому значения выше FL390/ниже FL330 не обрезаются. Источник её оценки: **Open-Meteo GFS, температура и геопотенциальная высота изобарических уровней 700–50 hPa**; оценка по градиенту температуры (не официальный продукт ICAO/WAFS).
6. Таблицы ветра/температуры/ISA получают **Windy Point Forecast API (модель GFS)**. Windy не предоставляет отдельный параметр тропопаузы. Windy Point Forecast не предоставляет ECMWF, а уровни 250 hPa и 100 hPa недоступны; между уровнями используется интерполяция (известное ограничение).

## Шаг 1 — GitHub (обновить проект)

В репозитории `soEasyGHB/windy-flight-planner-ICAO` замените исходники из полного ZIP v0.10.0 (включая папки `src`, `api`, `tests`, `tools`, `.github`, `public`, файлы `package.json`, `vercel.json`). Не удаляйте вашу существующую рабочую базу `public/navdata/*`: архив её не содержит; при полном копировании сохраните старую навигационную базу, затем при необходимости запустите синхронизацию.

В репозитории GitHub остаётся существующая публикация в Windy через Actions → `publish-plugin` → **Run workflow**. Для неё, как и раньше, нужен секрет **`WINDY_API_KEY`** (для *публикации плагина*, не для прогноза по точкам).

## Шаг 2 — Vercel (защитить ключ API)

Vercel → ваш проект, подключённый к этому GitHub-репозиторию → Settings → Environment Variables. Добавьте:

- **`WINDY_POINT_FORECAST_KEY`** — реальный ключ *Windy Point Forecast API*, отдельный от ключа Map API/публикации.
- *Необязательно*: `WINDY_ALLOWED_ORIGINS` — список разрешённых `Origin` через запятую. По умолчанию: `https://www.windy.com,https://windy.com,https://plugins.windy.com`. Если вы используете другой официальный домен Windy или локальную среду тестирования, внесите его сюда. CORS-защита не заменяет серверный rate limiting.

Нажмите **Redeploy** (требуется после добавления переменных).

API заработает по адресу `https://ВАШ-ДОМЕН.vercel.app/api/windy-forecast`, но открывать его в браузере напрямую не нужно: он принимает **только POST**. Ключ не помещается в `src`, браузер или GitHub и не возвращается клиенту.

**Важно:** бесплатный **Testing** ключ Windy возвращает случайно изменённые/перемешанные прогнозы, только для проверки интеграции, **не для получения близких к фактическим данных**. Для этого нужен подходящий рабочий тариф Point Forecast; ECMWF не входит даже в платный Point Forecast по условиям Windy на момент v0.10.0. Использование Windy требует соблюдения его условий и тарифных лимитов.

## Шаг 3 — в Windy (один раз)

1. Откройте опубликованный плагин Windy → **Настройки** → **Источник данных Windy Point Forecast**.
2. Введите **корневой адрес Vercel** `https://ВАШ-ДОМЕН.vercel.app` (без `/api/...`). Он сохранится в `localStorage` текущего браузера.
3. Введите маршрут, дату и время ETD UTC → **Построить маршрут** → **Наш планировщик полёта** → **Построить метеопрофиль и подобрать эшелоны**.
4. Если Vercel или Windy API не настроены, профиль покажет понятную ошибку, а **не заменит данные Windy** незаметно прогнозом другого поставщика.
5. Проверьте, что внизу профиля выводятся обе рекомендации FL. На штатный Windy Route Planner переходят через отдельную карточку ниже.

## Проверки после загрузки GitHub

GitHub Actions `publish-plugin` выполняет:

```bash
npm install
npm run check:tree
npm run check:imports
npm run check:exports
npm run typecheck:core
npm test
npm run build
npm run verify:release
```

Если GitHub Actions завершился с ошибкой — не публикуйте релиз. Чтобы проверить ключ Vercel, откройте в Windy маршрут на время в пределах горизонта GFS: если key отсутствует, ответ прокси будет `503` с указанием `WINDY_POINT_FORECAST_KEY`.

## Существенные ограничения

- Эти эшелоны — **только сравнение продольного ветра**. Не учтены массы, оптимизация топлива, climb/descent, buffet margins, допустимые FL/направления, границы RVSM, MET/ATC/airspace, турбулентность или требования FCOM. Рекомендация **не является** оптимальным/разрешённым эшелоном для полёта.
- Геометрия использует прямые между распознанными именованными FIX; ATS-трассы и ограниченные/неизвестные сегменты не восстанавливаются. ETA при TAS450 kt не учитывает ветер.
- Windy Point Forecast GFS даёт численную модель, а **не фактическую атмосферу**. Информация может отличаться от выбранного слоя ECMWF на карте Windy. FL рассчитываются интерполяцией из редких изобарических уровней.
- Если Open-Meteo не вернул высоту/температуру для тропопаузы, рисуются только подтверждённые участки (без выдуманной линии) и показывается «нет достаточных данных».
- Публичный серверless-endpoint Vercel нужен исключительно как прокси, *не требуется отдельный постоянный сервер*. Для production доступной интеграции рекомендуется добавить полноценное ограничение запросов по серверным квотам/пользователям.
- Не использовать как официальный план полёта, источник SIGMET/WAFS или средство оперативной навигации.
