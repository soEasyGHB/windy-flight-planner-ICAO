По умолчанию открывается слой «Турбулентность» для FL350. Для карты запрашивается `levelsRange=300h-200h` (примерно FL300–FL386 ISA), ближайший из публично документированных диапазонов к FL300–FL390. Параметр `level` синхронизируется отдельно; после асинхронной загрузки слоя диапазон повторно устанавливается несколько раз в течение 3 секунд, после чего плагин прекращает попытки. Если Windy не подтвердил изменение, это явно отражается в скрытых диагностических сообщениях.

# Windy Flight Route Analyzer — v0.8.5 (полный исходный проект)

Версия проверена на основе предыдущей полной v0.8.4. Это **полный набор исходников**, а не инкрементальное обновление. Файлы `src/routePlanner.ts`, `src/plannerPointNames.ts`, `src/flightAltitude.ts`, `src/xplane.ts`, `src/navdataConfig.ts` и все их импорты входят в архив.

## Главная панель

Ровно четыре последовательных блока:

1. **Ввод маршрута** — OFP / ICAO, построить, очистить.
2. **Ввод времени вылета UTC** — дата и время друг под другом, затем FL и TAS (по умолчанию 450 kt).
3. **Выбор слоя погоды** — только грозы, осадки, турбулентность и радар.
4. **Планировщик полёта** — только скачать GPX и открыть Windy Route Planner.

Серые карточки и поля. Офлайн-HTML/PDF, профиль ветра/температуры/ISA, диагностика и предупреждения находятся в закрытых по умолчанию «Настройках».

«Настройки» по умолчанию свернуты. Внутри — все сообщения, ошибки, диагностика, модель Windy, параметры экспортного снимка, подробный прогноз FL300–FL400 и навигационная база. Ошибки не скрываются от диагностики навсегда — только с основного экрана.

## Метеорология, высоты и время

- При изменении FL карта Windy получает ближайший доступный изобарический `level`. Для турбулентности используется `levelsRange`; FL350 → запрос диапазона 300h–200h (если слой/модель допускают).
- Грозы/осадки и радар не подтверждают точную высоту FL350: это двумерные слои или наблюдения. Никакой ложной высотной привязки не делается.
- По каждой **именованной** точке OFP: ETA рассчитывается из ETD, расстояния по известной геометрии маршрута и TAS без ветровой поправки. Выбор строки меняет `timestamp` Windy на ETA.
- Профиль FL300, FL310, …, FL400: ветер, температура и ISA deviation интерполируются между изобарическими уровнями Open-Meteo. Модель таблицы отличается от модели выбранного слоя Windy.
- Тропопауза и метеоиндикаторы приближённые, не сертифицированная авиационная прогностическая продукция.

## Маршруты и навигационная база

- Ввод маршрута поддерживает FIX, координаты и названия ATS, использование данных X-Plane после конвертации в `points.csv`, `airways.csv`, `manifest.json`.
- При известных обоих концах ATS разворачивается по графу геометрии. Нераспознанные трассы и пропущенные точки **не соединяются** линией. Имена синтетических вершин не показываются.
- Неоднозначные идентификаторы требуют проверки. GPX экспортирует **только именованные FIX**, отдельными GPX-маршрутами `<rte>` для подтверждённых участков. Промежуточные ATS-вершины и `<trk>` отсутствуют; при разрывах файл обозначается PARTIAL. Windy поддерживает импорт GPX, но детали работы с `<rte>` необходимо подтвердить на устройстве.
- Исходные координаты X-Plane не включены. Используйте только данные, на распространение которых у вас есть права.
- `src/navdataConfig.ts` содержит публичный адрес репозитория. Запись и чтение результатов синхронизации — через GitHub Actions и публичные CSV.

Аэропорты с кодом ВПП в начале/конце строки, например `UUEE24C ... OMDB30R`, нормализуются до `UUEE ... OMDB`. Синтетический тест `Y12` проходит с данными AWY1100; наличие реальной `Y12` зависит от загруженной пользователем базы AIRAC.

## Офлайн-отчёт

HTML содержит самодостаточную схему маршрута, имена точек и, если загружен, прогноз. Чтобы сохранить **погодную карту Windy**, выберите слой/время и приложите сделанный вами PNG/JPEG/WebP-скриншот. Плагин не извлекает закрытые тайлы или WebGL-слой Windy. PDF получается печатью автономного HTML из Safari.

## Установка и проверка

```bash
npm install
npm run check:imports
npm run check:exports
npm run check:tree
npm run typecheck:core
npm test
npm run build
npm run verify:release
```

`verify:release` проверяет соответствие `package.json`, `pluginConfig.ts` и `dist/plugin.json`; а также наличие `dist/plugin.js` и `dist/plugin.min.js`. **Не публикуйте**, если эта проверка не прошла.

GitHub Actions `publish-plugin` перед загрузкой на сервер Windy заново проверяет исходники, выполняет тесты, сборку и `verify:release`.

## Google Drive → GitHub → Windy

В GitHub → Settings → Secrets and variables → Actions → Variables установите `GDRIVE_NAVDATA_FOLDER_URL` на публичную Google Drive-папку **с одним ZIP**. ZIP должен содержать `earth_fix.dat`, `earth_nav.dat`, `earth_awy.dat` одного AIRAC. Запускайте Actions → `sync-gdrive-navdata` → Run workflow. Обновлённые CSV публикуются в `public/navdata/`. Повторная публикация версии плагина для нового AIRAC не требуется.

Содержимое `public/navdata` в этом ZIP намеренно **не содержит** демонстрационных данных и не перезаписывает вашу ранее опубликованную базу. Для нового пустого репозитория первоначально выполните синхронизацию.

## Границы проверки

Строгий TypeScript core, статические проверки импортов/экспортов и локальные Node-тесты выполнены. **Компиляция Rollup/Windy в среде подготовки недоступна** из-за отсутствия локально установленных npm-зависимостей и доступа к npm-реестру; она должна пройти в Codespaces или GitHub Actions. Работа в мобильном Windy/iPad и корректность передачи координат в конкретной версии штатного Route Planner требуют проверки на устройстве.

Проект предназначен для предварительного обзора, **не является** источником достоверных навигационных данных, SIGMET или официального метеобрифинга.
