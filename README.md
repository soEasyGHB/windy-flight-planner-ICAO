# Windy Flight Route Analyzer v0.5.1 — X-Plane ZIP → Windy (iPad)

**Это обновление уже созданного Windy-плагина, не новое приложение.** Трасса рисуется поверх Windy, остаются выбор метеослоёв Windy и экспериментальный высотный погодный анализ через Open-Meteo (это отдельный источник).

## Два независимых режима работы

### А. Импорт X-Plane прямо в Windy, без публикации файлов

На iPad сделай ZIP с тремя файлами и выбери **«Добавить ZIP или три файла X-Plane»** → ZIP должен содержать:

- `earth_fix.dat` — точки (enroute + terminal);
- `earth_nav.dat` — радиомаяки NDB/VOR/DME;
- `earth_awy.dat` — сегменты трасс.

Нажми **«Импортировать X-Plane в Windy»**. Исправление v0.5.1 убирает `accept=.dat`: iPad теперь может выбирать ZIP и .txt, а ZIP читает прямо на устройстве. Программа локально прочитает текст, сверит AIRAC в заголовках, пересчитает маршруты и покажет число найденных точек/сегментов. Вставь ICAO-route и нажми «Построить маршрут».

Этот вариант **не передаёт** содержимое X-Plane на GitHub/Windy-серверы; загруженные данные действуют лишь в открытой вкладке. При перезапуске или обновлении Windy потребуется выбрать файлы снова. Он подходит для данных, которые нельзя публиковать, но перед использованием всё равно соблюдай лицензию источника.

### Б. Через GitHub: загрузить один раз и использовать с iPad

Для набора, **который законно разрешено публиковать**, можно хранить один ZIP с тремя `.dat` в публичном GitHub-репозитории. GitHub Actions конвертирует их в `public/navdata/points.csv`, `airways.csv` и `manifest.json`; Windy получает их по HTTPS при открытии плагина или по кнопке **«Обновить базу из GitHub»**. Вручную конвертировать ничего не нужно.

* Нажми в Windy кнопку **«Открыть загрузку файлов GitHub»** — откроется страница загрузки файлов папки `navdata-input/` в GitHub. Если браузер не открыл её, зайди в `https://github.com/ТВОЙ-ЛОГИН/ТВОЙ-РЕПОЗИТОРИЙ` → `navdata-input` → `Add file` → `Upload files`.
* Выбери один `xplane-navdata.zip` с `.dat` одного AIRAC и нажми **Commit changes** на GitHub. Должен оставаться ровно один ZIP в папке.
* Проверь GitHub → **Actions** → `build-navdata` (зелёная галочка); при необходимости запусти **Run workflow**. Если появляется ошибка `Permission denied` для git push, включи **Settings → Actions → General → Workflow permissions → Read and write permissions**.
* В Windy укажи публичный GitHub репозиторий (`https://github.com/USERNAME/REPO`) и нажми **«Обновить базу из GitHub»**.

**Безопасность:** браузерный плагин **не** загружает файлы напрямую в твой GitHub-аккаунт — без GitHub OAuth/токена это было бы небезопасно. Кнопка открывает официальный загрузчик GitHub, подтверждение делается тобой. Репозиторий **должен быть Public**, чтобы Windy читал его без ключа. **Не размещай** закрытые, платные, лицензированные данные (Navigraph, Jeppesen, ICAO и т. п.) на публичном GitHub без прямого разрешения на публикацию.

## Обновить существующий проект через Codespaces на iPad

1. Скачай архив `Windy-Flight-Route-Analyzer-UPDATE-v0.5.0.zip` в «Файлы» iPad. В GitHub открой свой `windy-flight-planner` → `Code` → `Codespaces` → существующий Codespace.
2. Загрузи ZIP **в корень репозитория** через Explorer (контекстное меню → Upload).
3. Открой Terminal в Codespaces и запусти команды, находясь в корне репозитория:

   ```bash
   unzip -o Windy-Flight-Route-Analyzer-UPDATE-v0.5.0.zip
   npm install
   npm run build
   npm test
   git add -A
   git commit -m "Add X-Plane file import in Windy"
   git push
   ```

   ZIP содержит готовые файлы **с относительными путями проекта**, поэтому их не нужно переносить вручную. Если `git commit` сообщает `nothing to commit`, изменения уже сохранены.
4. Для обновления *интерфейса Windy-плагина* один раз выполни GitHub → **Actions → publish-plugin → Run workflow**. Секрет `WINDY_API_KEY` остаётся только в GitHub Secrets (не записывать его в код).
5. Открой Windy под своей учётной записью и включи свой приватно опубликованный плагин. Дальнейшее обновление **данных** в GitHub **не требует** повторной публикации плагина.

Подробно см. [НАВИГАЦИОННАЯ-БАЗА-iPad.md](./НАВИГАЦИОННАЯ-БАЗА-iPad.md).

## Сопоставление и ограничения

- Пример ICAO-маршрута: `TOGMO M56 ABAGI B105 NIMTA DCT MOLED`. Для известных точек показываются координаты. ATS-сегменты конвертируются в связанный граф; если цепочку не удалось подтвердить, будет предупреждение, а не заявленная точная трасса.
- Файлы X-Plane 11/12: XPFIX1101/1200, XPNAV1150/1200, XPAWY1101. Проверка AIRAC означает только **совпадение цикла в трёх заголовках**. Факт его текущей действительности не проверяется.
- Не импортируются SID/STAR/approach `CIFP`, `earth_424.dat`, airspace restrictions и NOTAM. **Не проверяются** направление сегментов `F/B`, нижние/верхние разрешённые эшелоны, применимость маршрута по региональным правилам. Следовательно, файл и линия на карте предназначены для **ознакомительного метеоанализа**, не для IFR-навигации и диспетчерского обеспечения.
- Прямая загрузка в браузере требует памяти (на больших глобальных базах iPad может работать медленно). Если импорт не помещается, используй GitHub Action для данных с разрешённой публикацией.
- Нельзя обещать завершение сборки Windy без запуска в реальном Windy. `npm test` и `npm run typecheck:core` проверяют конвертер/геометрию; команда `npm run build` проверяет UI Rollup/Svelte при установленных зависимостях.
