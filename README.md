# Windy Flight Route Analyzer — версия 1.1.1

Минималистичный плагин для визуализации проверенных точек OFP/ICAO на карте Windy, экспорта GPX и открытия штатного планировщика Windy.

## Интерфейс

- **Ввод маршрута:** увеличенное вдвое текстовое поле (8 строк), построение/очистка маршрута, подписи подтверждённых FIX на карте.
- **Планировщик полёта:** компактные поля даты и времени вылета (UTC) одно под другим по центру; только две кнопки — «Скачать GPX» (меню «Поделиться» на iPad или скачивание в браузере) и **«Открыть маршрут с UTC в Windy»** (штатный IFR-планировщик по URL с координатами и временем прогноза). Кнопка открытия пустого планировщика удалена.
- **Настройки:** только «Ошибки и предупреждения» и «Навигационные базы данных»; сообщения о частичном GPX видны только в диагностике.

## GPX

- **Имя файла:** при наличии двух подтверждённых аэропортов ICAO — `UUEE-UNNT.gpx`, `USSS-LTAI.gpx`. Суффикс ВПП (`UUEE24C`, `UNNT25`) отбрасывается. Для неполного маршрута добавляется `-PARTIAL`, например `UUEE-UNNT-PARTIAL.gpx`; если невозможно однозначно установить аэропорты, используется `windy-route.gpx` или `windy-route-PARTIAL.gpx`.
- **Время:** выбранный ETD UTC записывается как стандартный `<time>` **только на первую точку маршрута** (и её `<wpt>`, если подтверждена исходная точка), а также в `<fr:plannedDepartureUtc>` и читаемое описание. Время прохождения остальных FIX не выдумывается. Метаданные `<metadata><time>` не подменяются временем вылета.
- **Названия:** у каждой экспортируемой именованной точки есть `<name>`, `<cmt>`, `<desc>` как в `<rtept>`, так и в `<wpt>`. **Windy может отображать номера вместо имён**: это поведение интерфейса импортёра, которое невозможно гарантированно изменить содержимым GPX. В Windy Community зарегистрированы сообщения о пропаже имён точек при импорте в 2026 году.
- **Безопасность:** SID/STAR с цифрами около аэродромов пропускаются, если их геометрия неизвестна, неизвестный FIX в середине маршрута создаёт разрыв; неподтверждённые участки нельзя соединять вымышленными прямыми. GPX служит только для визуализации.

## Установка и проверки

Пошаговая установка: [INSTALL-v1.1.1.md](INSTALL-v1.1.1.md). Результаты тестирования: [AUDIT-v1.1.1.md](AUDIT-v1.1.1.md).

В проекте нет погодных API, Vercel, PDF/HTML-отчётов и отдельного метеопланировщика. `WINDY_API_KEY` используется только для публикации плагина. Не использовать для официального планирования IFR или навигации.

## Штатный IFR-планировщик по URL (версия 1.1.1)

Теперь кнопка **«Открыть маршрут с UTC в Windy»** строит обычную ссылку вида
`https://www.windy.com/route-planner/ifr/55.9726,37.4146;55.0126,82.6507?2026-11-16-18`
— это формат, подтверждённый пользователем в Windy. Передаются координаты непрерывного подтверждённого участка маршрута и время выбранного трёхчасового интервала UTC. Ссылка открывается через `<a href>` (удобно и на iPad), без недокументированной передачи через `rqstOpen`.

Дата/время берутся из существующих полей UTC. При изменении даты или времени ссылка обновляется автоматически, без перестроения маршрута. Формат URL Windy передаёт час на трёхчасовой сетке; например, 18:20 UTC станет 18:00 UTC в URL, **точное время 18:20 сохраняется в GPX**. При частичном маршруте передаётся самый длинный непрерывный подтверждённый участок, без соединения неизвестных точек. Подробности доступны в диагностике.

В версии 1.1.1 **удалена** кнопка открытия пустого планировщика Windy. Сохранены только **«Скачать GPX»** и **«Открыть маршрут с UTC в Windy»**. Поля даты/времени занимают примерно вдвое меньше вертикального пространства: высота ввода 40 px и компактные подписи. Поле маршрута увеличено с 4 до 8 строк (минимальная высота 172 px).

В версии 1.1.1 ссылка на штатный планировщик обновляется также непосредственно при нажатии: фактические значения даты/времени считываются из полей, чтобы iPad не открывал предыдущий ETD до срабатывания события `change`.
