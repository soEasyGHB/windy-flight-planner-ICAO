## v0.7.2 — работающие действия и прогноз по именованным точкам FL300–FL400

- **Windy Route Planner**: кнопка всегда реагирует на нажатие; если маршрут не подтверждён (неразрешённая ATS-трасса, двусмысленные FIX, разрыв), отображается точная причина. Для подтверждённого маршрута строится URL `windy.com/distance/...`; он открывается в новой вкладке, а также появляется явная ссылка **«Открыть подготовленную ссылку в Safari»** на случай ограничений встроенного браузера iPad.
- **GPX**: если маршрут подтверждён, на iPad используется системное меню Share → «Сохранить в Файлы» при поддержке браузером; иначе обычная загрузка `.gpx`. Случайный неверный маршрут не экспортируется. На мобильной версии не гарантирована автоматическая загрузка или программное открытие штатного планировщика: это зависит от Windy/iPadOS.
- **Время Windy = ETD**: вызывает поддерживаемый `store.set('timestamp', UTC_TIMESTAMP)` и показывает результат либо причину отказа, например время вне прогнозного горизонта.
- **Прогноз по маршруту**: вместо S1/S2 рассчитывается ETA **каждой именованной точки плана** (например TOGMO, ABAGI, NIMTA), учитывая при расчёте расстояния невидимые вершины ATS. В выпадающей панели для каждой точки — **FL300, 310, …, 400**, ветер (направление/скорость), температура и отклонение от ISA. В CSV также экспортируется каждая точка × эшелон.
- Температура и ветер интерполируются между изобарическими уровнями на логарифмической шкале давления. Используется **Open-Meteo Best Match**, поэтому значения могут отличаться от выбранного слоя Windy; это не официальный aviation weather product. TAS постоянная (по умолчанию 450 kt), ETA без ветровой поправки.
- Не изменены Google Drive → GitHub навигационная база, траекторная логика и подписи только именных FIX.

Локально прошли `npm run typecheck:core` и `npm test`, включая новые тесты имени каждой точки, FL300–400 и ветра при переходе через 360°. Полную сборку плагина `npm run build` нужно проверить в GitHub Codespaces: в среде подготовки нет установленных Windy SDK/Rollup пакетов (`rollup: not found`).

## v0.7.1 — передача маршрута в штатный Windy Route Planner

Кнопка **«Открыть в Windy Route Planner»** передаёт координаты всех подтверждённых участков по официально описанному формату ссылки Windy `/distance/lat,lon;...`. Готовый маршрут открывается в том же окне. Если iPad не поддерживает маршрут по ссылке или URL слишком длинный, нажмите **«Скачать GPX (резерв)»** и откройте его штатным Import GPX.

- Сохраняются имена только маршрутных точек, сегменты воздушных трасс используются для геометрии.
- При разрывах маршрута, неоднозначных координатах и нераскрытых трассах передача заблокирована.
- При сокращении URL погрешность геометрии ограничена 1 NM, причём ни одна явно указанная в плане точка не удаляется. Если этого недостаточно для безопасной длины ссылки, плагин откажется и предложит GPX с полной геометрией.
- По ссылке Windy передаются **только координаты**, поэтому в штатном планировщике отдельно установите UTC ETD, TAS (например 450 kt) и IFR. Их автоматическая передача официальным форматом URL не предусмотрена.
- Не заменяет оперативное IFR-планирование; используйте актуальные официальные данные для полёта.

**Проверка:** тесты генерации ссылок, защиты от разрывов, упрощения траектории и GPX запускаются через `npm test`. Поведение передачи ссылки в установленном приложении Windy на iPad проверяется после публикации.

# Windy Flight Route Analyzer v0.7.0

Навигационная база данных (Google Drive → GitHub → Windy), маршрут ICAO/OFP, карта, высотная погода и UTC-время.

## Новое в v0.7.0

- В интерфейсе база называется **«Навигационная база данных»**. Технический исходный формат `.dat` не изменён; сведения о происхождении данных и лицензии остаются обязательными.
- В блоке **«Вылет и скорость полёта»** отдельно задаются дата UTC, время UTC и **TAS 450 kt** (значение по умолчанию).
- Windy получает выбранную дату и время через `store.set('timestamp', …)` при построении маршрута, выборе/изменении ETD и по кнопке «Время Windy = ETD». Если ETD за пределами горизонта модели, карта может отказать в установке времени.
- По кнопке **«Открыть метеоразрез маршрута»** строится **отдельная нижняя панель нашего плагина**, не штатное окно Windy Distance & Planning. В ней отображаются ETA и расстояние, ветер на выбранном FL, ISA deviation, оценочная тропопауза и вертикальные значения по уровням 500–100 hPa (переключение ветер/ISA/температура).
- При выборе точки в разрезе временная шкала Windy переключается на её примерное **ETA**.
- Сохранено из прошлых версий: Google Drive и GitHub Actions, границы разбора ATS-трасс, защита от ложных перелётов через океан, только реальные имена RNAV/FIX на карте (не M56-2 и аналогичные вспомогательные вершины), выбор слоя и эшелона.

## Установка через GitHub Codespaces с iPad

1. Установи обновление поверх работающей версии **v0.6.3**; новую базу Google Drive загружать не надо.
2. Скачай `Windy-Flight-Route-Analyzer-UPDATE-v0.7.0.zip`, отправь его через **Codespaces → Explorer → Upload** в корень репозитория (рядом с `package.json`).
3. В Codespaces → Terminal проверь, что не выполняется merge/rebase, и выполни:

```bash
git status
git pull --ff-only origin main
unzip -o Windy-Flight-Route-Analyzer-UPDATE-v0.7.0.zip
npm install
npm run typecheck:core
npm test
npm run build
```

4. **Только если все команды завершились успешно**:

```bash
git add src/plugin.svelte src/pluginConfig.ts src/weather.ts package.json tests/test_weather.mjs README.md УСТАНОВКА-v0.7.0-iPad.md
git commit -m "Add UTC ETD and meteorological profile v0.7.0"
git push origin main
```

5. На GitHub открой **Actions → publish-plugin → Run workflow**. Версия плагина = `0.7.0`, чтобы Windy не отклонил повторную публикацию старой версии.
6. После зелёной отметки обнови/перезапусти Windy. Построй маршрут; введи дату UTC, время UTC и TAS. Нажми «Открыть метеоразрез маршрута» и при необходимости выбирай столбец точки для изменения времени на карте.

При `CONFLICT`, `non-fast-forward` или `failed` **не выполняй `git push --force`**, сначала проверь конфликт.

## Важные ограничения

- ETA = длина геометрии маршрута / постоянная **TAS**. Поправка на попутный/встречный ветер, climb/descent, ограничения скоростей и реальные полётные планы FMC здесь не рассчитываются.
- Нижняя панель и данные по высотам — **Open-Meteo Best Match**, а не выбранная модель карты Windy. Несовпадения с ECMWF/GFS на карте возможны. Для внешних данных требуется доступ в интернет; ограничение Open-Meteo и горизонта прогноза может препятствовать загрузке.
- **ISA deviation** — температура модели минус ISA при стандартной барометрической высоте соответствующего уровня.
- **Тропопауза** — ориентировочная оценка по температуре и геопотенциальной высоте на нескольких изобарических уровнях, не полное WMO-определение и не официальный авиационный SIGWX. Если недостаточно уровней — `н/д`.
- Наш UI-профиль не открывает и не заполняет закрытый внутренний Windy Route Planner автоматически: такого документированного публичного интерфейса импорта геометрии в его внутреннюю панель мы не подтвердили.
- Нельзя публиковать коммерческие навигационные данные, если лицензия запрещает распространение. Навигация и прогнозы здесь только для визуального анализа, не для эксплуатационных решений.

## v0.7.3 — диагностика GPX/Route Planner при неполном маршруте

* Кнопки больше не показывают только общую ошибку. В панели под кнопками показаны конкретные неизвестные FIX, воздушные трассы, разрывы между точками и неоднозначные идентификаторы.
* При разрывах **«Скачать GPX по участкам»** создаёт `windy-route-PARTIAL.gpx` с отдельными `<trkseg>`, не проводя линию сквозь неизвестные участки. Файл **не является полным маршрутом**; в GPX это явно помечено. Изолированные известные точки сохраняются как `<wpt>`.
* **«Открыть доступный участок в Windy»** может передать только **один самый длинный непрерывный подтверждённый участок**. Это не замена передаче всего OFP; конкретные начальный и конечный пункты показываются в сообщении после нажатия.
* Если несколько навигационных пунктов имеют одно название, пользователь должен вручную проверить координаты в таблице и включить подтверждение для экспорта. Это не делает координаты достоверными автоматически.
* Алгоритм разбора маршрута и Google Drive → GitHub синхронизация не изменены. Не нужно повторно загружать навигационную базу.

Только предварительная визуализация погодных условий, не для навигации. `npm test` и `npm run typecheck:core` проверены локально; окончательная сборка плагина должна выполняться в Codespaces.
