# Windy Flight Route Analyzer v0.6.2 — подписи точек + Google Drive + GitHub

**Главная цель:** просто заменять ZIP с навигационной базой X-Plane 11/12 в папке Google Drive; GitHub Actions обрабатывает его автоматически, а Windy отображает последнюю опубликованную навигационную базу.

## Исправление v0.6.2: названия точек на карте

- Названия FIX / RNAV / VOR / аэропортов, **явно присутствующих в плане полёта**, рисуются как постоянные подписи Leaflet (`permanent tooltip`) поверх оранжевой линии.
- Промежуточные геометрические вершины ATS (`M56-2`, `B105-3`, ...) не подписываются, но сохраняют форму линии.
- Метки именованных точек отображаются и при разрывах маршрута; разорванные участки по-прежнему не соединяются.
- В панели добавлен счётчик подписей. Если он больше 0, но на карте надписей нет, следует проверить кеш Windy/обновить плагин.
- Схема Google Drive → GitHub и навигационная база **не меняются**. Повторная загрузка navdata не требуется.

### Быстрое обновление на iPad

1. В GitHub Codespaces откройте Terminal; убедитесь, что `git status` не сообщает о незавершённом merge/rebase.
2. Загрузите `Windy-Flight-Route-Analyzer-UPDATE-v0.6.2.zip` в корень проекта.
3. Выполните команды из блока ниже; при ошибке остановитесь, не выполняйте `push --force`.

```bash
git pull --rebase origin main
unzip -o Windy-Flight-Route-Analyzer-UPDATE-v0.6.2.zip
npm test
npm run build
git add src/navdb.ts src/plugin.svelte src/pluginConfig.ts package.json tests/test.mjs README.md
git commit -m "Show named waypoints on map v0.6.2"
git push origin main
```

После успешного `push` зайдите GitHub → Actions → `publish-plugin` → Run workflow. Версия увеличена до `0.6.2`, поскольку Windy не позволяет публиковать дважды тот же номер.

## Что сохранено

- Ввод OFP/ICAO: FIX, VOR, ATS (M56/B105/G242/UG67 и т. д.), DCT и смены скорости/FL.
- Исправления маршрутов v0.5.2: цифровые имена ATS не трактуются как американские радиомаяки, географические скачки блокируются, неоднозначные идентификаторы помечаются.
- Исправление v0.5.3: только реальные маршрутные точки подписываются на карте; промежуточные вершины ATS остаются в оранжевой линии **без подписей**.
- Выбор погодного слоя Windy, модель, FL и экспериментальный разрез погоды. В этой версии ZIP НЕ загружается в Windy.

## Как настроить на iPad (один раз)

1. В Google Drive создайте папку `Windy-NAVDATA`. Поместите в неё **ровно один** `xplane-navdata.zip`, внутри которого `earth_fix.dat`, `earth_nav.dat`, `earth_awy.dat` одного цикла AIRAC. Можно вместо ZIP положить **ровно три `.dat`**; не храните там одновременно старые и новые версии.
2. В Drive → «Поделиться» установите папке **«Все, у кого есть ссылка» → «Читатель»**. Такая папка доступна посторонним по ссылке: не загружайте коммерческие данные, которые запрещено распространять.
3. Скопируйте ссылку **на папку**, например `https://drive.google.com/drive/folders/XXXXXXXX`.
4. На GitHub откройте репозиторий → **Settings → Secrets and variables → Actions → Variables → New repository variable**. Создайте переменную `GDRIVE_NAVDATA_FOLDER_URL`, значение — скопированная ссылка.
5. Перейдите **Actions → sync-gdrive-navdata → Run workflow**. Если он завершится зелёным, GitHub обновит `public/navdata/points.csv`, `airways.csv`, `manifest.json` (наши конвертированные точки и сегменты). Автоматическая проверка идёт **раз в сутки**, запуск по cron не гарантирует точное время.
6. В Windy откройте плагин → **«Проверить новую базу»**, либо закройте и снова откройте плагин; убедитесь, что появились AIRAC и количество точек.

**Существенное ограничение:** существующий репозиторий `soEasyGHB/windy-flight-planner-ICAO` на скриншотах был **Private**. Браузер Windy не может читать сырые CSV из приватного GitHub без токена. Для этой версии понадобится **публично доступный** навигационный репозиторий, содержащий только разрешённые к открытому распространению данные. Сделать основной репозиторий публичным — лишь один вариант, и он не подходит для коммерческих navdata. Простой ссылки на частную папку Drive недостаточно: напрямую Windy потребовалась бы авторизация Google/API-ключ либо сервер-посредник.

### Резерв без Drive

Если скачивание Google Drive перестанет работать, сохранилась схема **GitHub → navdata-input → загрузить ZIP → Commit changes**: `build-navdata` обработает новые файлы. После этого Windy нажатием «Проверить новую базу» прочитает их (при публичном доступе к базе).

### Диагностика

- `sync-gdrive-navdata` ошибка `Permission Denied`: проверь «Все, у кого есть ссылка» и разрешение на скачивание.
- `No valid airways`: проверь формат X-Plane/одинаковый AIRAC и наличие `earth_awy.dat`.
- `No changes`: все три исходных файла побайтно одинаковы с последней опубликованной базой; это нормальный результат.
- `GitHub не отдал navdata-файлы`: GitHub private (или CSV ещё не созданы). Никакие GitHub PAT или Google cookies не следует вставлять в код плагина.
- Для защиты от повреждённого обновления GitHub Actions не коммитит новую базу при ошибке скачивания, ZIP или AIRAC.

### Ограниения точности и лицензирования

- Плагин — **только визуализация маршрута и метеоанализа**. X-Plane navdata не проверяется на действующие разрешённые высоты/направления ATS, ограничения воздушного пространства, NOTAM, RAIM, SIGMET, validity of route, и не заменяет утверждённую эксплуатационную навигационную базу.
- У Google Drive бывают ограничения выдачи и скачивания публичных файлов, поэтому `gdown` может временно не работать, даже если ссылка открывается в Safari.
- Нельзя делать общедоступными персонально лицензированные Navigraph, Jeppesen или другие данные, если условия лицензии не позволяют этого. При таком ограничении следует оставить локальный импорт версии v0.5.3.
- Реальное скачивание из Google Drive здесь не тестировалось из-за отсутствия доступной публичной папки пользователя. Проверены конвертер и логика обновления на локальных фикстурах.


## Исправление v0.6.3 (27.10.2026)

Устранён вызов устаревшего `L.circleMarker(...)`, который мешал открытию панели в текущем Windy leaflet-gl. Использован `new L.CircleMarker(...)`, с резервной меткой `new L.Marker`/`new L.DivIcon`. Ошибки отдельных подписей перехватываются; сохраняются построение маршрута, отображение только реальных waypoint-подписей и синхронизация Google Drive → GitHub.

Публикация в Windy требует новой версии 0.6.3 и успешной сборки в GitHub Actions.
