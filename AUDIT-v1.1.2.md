# Аудит релиза 1.1.2

## Исправление

- Сохранён проверенный пользователем формат URL `/route-planner/ifr/<coordinates>?YYYY-MM-DD-HH` и алгоритм трёхчасового округления из 1.0.3/1.1.1.
- URL теперь создаётся только при явном нажатии «Сформировать ссылку с UTC», с непосредственным чтением DOM-полей.
- Ссылка видна в интерфейсе и открывается обычным `<a href>`; при клике не изменяется.
- При изменении даты, времени или маршрута старый URL удаляется; некорректная дата/время не создаёт ссылку.
- Добавлено копирование URL и явное сравнение выбранного UTC с UTC, закодированным в ссылке.
- GPX, база данных, имена точек, формат имени файла, основной ввод маршрута и настройки сохранены.

## Проверки

- `npm run check:tree`, `npm run check:build-config`, `npm run check:imports`, `npm run check:exports`, `npm run typecheck:core`, `npm test` — выполняются отдельно.
- Проверены ручное формирование URL, чтение DOM в обход устаревшего Svelte-состояния, повторное формирование, смена 18→21 UTC, отсутствие старого `href` при ошибке и сброс при изменении полей.
- Набор тестов включает `check:startup` с имитацией загрузки компонента; тесты URL и GPX проверяются отдельно.
- Полный `npm run build`/`npm run test:release` требует Rollup/Svelte из npm, поэтому результат сборки должен быть получен в Codespaces до публикации.
- Фактическое применение времени в штатном планировщике Windy возможно подтвердить только в Windy (в т.ч. на iPad).
