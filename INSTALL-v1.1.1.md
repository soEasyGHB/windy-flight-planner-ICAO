# Windy Flight Route Analyzer — выпуск 1.1.1

## Что исправлено

В версии 1.1.0 был уменьшен нативный выбор даты и времени с 42 до 28 px. Формат URL IFR и алгоритм округления UTC при этом **не менялись** по сравнению с 1.0.3. Однако ссылка в 1.1.0 пересчитывалась только по событию `change`, поэтому на некоторых устройствах могла открываться со старым временем, если нативный выбор времени ещё не инициировал это событие.

В 1.1.1 поля имеют высоту 40 px (по-прежнему компактные), теперь обрабатывают `input` и `change`. Дополнительно при **самом нажатии на ссылку** плагин синхронно читает значения обоих полей, повторно рассчитывает ссылку и подставляет её в настоящий `href` до открытия новой вкладки. Если UTC введён некорректно, переход со старым временем блокируется; текст ошибки доступен в «Настройки → Ошибки и предупреждения».

Сам формат URL проверенной версии 1.0.3 остался неизменным:
`https://www.windy.com/route-planner/ifr/55.9726,37.4146;55.0126,82.6507?2026-11-16-18`

**Ограничение:** URL использует трёхчасовые интервалы (например, 18:20 UTC → 18:00 UTC), GPX сохраняет точное время. При времени вне доступного диапазона прогноза Windy может игнорировать параметр URL; это зависит от самого сервиса.

## Как установить в GitHub Codespaces

Загрузить `Windy-Flight-Route-Analyzer-FULL-v1.1.1.zip` в корень репозитория и выполнить:

```bash
unzip -o Windy-Flight-Route-Analyzer-FULL-v1.1.1.zip
npm run cleanup:legacy
npm install --no-audit --no-fund
npm run test:release
```

**Только после успешного `test:release`**:

```bash
git add -A -- . ':(exclude)*.zip' ':(exclude)*.sha256'
git status --short
git commit -m "Fix Windy UTC handoff v1.1.1"
git push origin main
```

Затем GitHub → Actions → `publish-plugin` → Run workflow (main). Секрет `WINDY_API_KEY` нужен только для публикации, не для GPX/URL.

## Как проверить на iPad

1. Построить маршрут, например UUEE–UNNT, и выбрать дату, попадающую в доступный прогноз Windy.
2. Установить **18:00 UTC**, открыть маршрут по кнопке и проверить время вылета в штатном планировщике.
3. Изменить время на **21:00 UTC, не перестраивая маршрут**, и повторить. Это проверяет, что ссылка не осталась со старым значением.
4. Если URL в настройках показывает новое время, а Windy применяет другое, проблема уже на стороне обработки ссылки штатным планировщиком (или время вне прогнозного диапазона).

Расчёты и маршруты исключительно справочные, не использовать в качестве официальных навигационных данных.
