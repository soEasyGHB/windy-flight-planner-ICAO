# Windy Flight Route Analyzer v0.10.5 — открыть маршрут в штатном планировщике без GPX

## Что изменено

После нажатия **«Построить маршрут»** появляется главная кнопка **«Открыть маршрут в штатном планировщике Windy»**. Она использует документированный Windy URL `https://www.windy.com/distance/lat,lon;lat,lon;...`, открывает отдельную вкладку Windy и загружает координаты выбранного маршрута в его штатный инструмент Distance & Planning. **Не нужно скачивать или импортировать GPX.** Ключ Windy Point Forecast и Vercel не нужны. Резервные варианты сохранены: GPX, «Поделиться» на iPad, попытка открытия в текущем окне через Windy broadcast (экспериментальная).

**Ограничения:** ссылка передаёт только координаты в порядке маршрута. Ни UTC ETD, ни TAS, ни выбранный FL, ни расчёт Windy с метеоданными Open-Meteo через ссылку не задаются. Проверь параметры в Windy. Если маршрут неполон (неразрешённые точки, неоднозначные FIX, разрывы или нераскрытые ATS), передаётся только самый длинный подтверждённый участок, и **пользователю явно показывается предупреждение**. Если нет непрерывного участка хотя бы из двух точек, кнопка заблокирована. Нет искусственных соединений через пропущенные точки; длинные маршруты не обрезаются молча. Наличие `'/distance/'` в публичной документации подтверждено, но открытие в конкретной версии Windy и на iPad требуется проверить после публикации.

Официальный формат: https://community.windy.com/topic/77/windy-com-url-parameters (раздел «Open distance & planning tool with a track»).

## Команды GitHub Codespaces

1. Загрузите `Windy-Flight-Route-Analyzer-FULL-v0.10.5.zip` в корень репозитория.
2. В терминале, из корня репозитория, запустите:

```bash
unzip -o Windy-Flight-Route-Analyzer-FULL-v0.10.5.zip
rm -f src/windyWeather.ts api/windy-forecast.js tests/test_windy_proxy_v010.mjs
npm install --no-audit --no-fund
npm run test:release
```

`npm run test:release` должен пройти полностью: структура проекта, TypeScript, все тесты, Rollup/Svelte, содержимое `dist`. Если команда завершилась ошибкой — **не публикуйте**.

3. Только после успеха:

```bash
git add -A -- . ':(exclude)*.zip' ':(exclude)*.sha256'
git status --short
git commit -m "Add direct Windy route planner link v0.10.5"
git push origin main
```

Проверьте статус перед коммитом: не включайте ключи, пароли, токены и случайные ZIP. Если рабочая ветка не main, укажите её имя.

4. В GitHub → Actions → `publish-plugin` → Run workflow → main запустите публикацию. Секрет `WINDY_API_KEY` нужен **только для публикации самого плагина**, не для открытия маршрута по ссылке.
5. После успешной публикации обновите Windy. Введите маршрут, нажмите **«Построить маршрут»**, затем **«Открыть маршрут в штатном планировщике Windy»**. Откроется новая вкладка. Проверьте порядок точек, боковой маршрут и установки ETD/TAS/FL в Windy.

## Проверки

`tests/test_windy_distance_link_v0105.mjs` проверяет формат URL, порядок координат, десятичные координаты, полный и частичный маршрут, неразрешённые точки, чрезмерно длинный URL, наличие реальной ссылки `target="_blank"`, сброс устаревшего маршрута и сохранность GPX. Дополнительные ограничения и выполненные проверки — в `AUDIT-v0.10.5.md`.
