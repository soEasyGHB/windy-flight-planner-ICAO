# Установка Windy Flight Route Analyzer v0.10.2 — без ключа метеоданных

## Что изменилось

- Таблица FL300–FL400, вертикальный метеопрофиль, составляющие ветра, ISA и рекомендации чётных/нечётных эшелонов автоматически получают исходные параметры **напрямую из Open-Meteo NOAA GFS**.
- Для метеоданных **не требуются** `WINDY_POINT_FORECAST_KEY`, Windy Professional API, Vercel, отдельный сервер или адрес сервера в интерфейсе.
- Тропопауза оценивается из **той же почасовой выборки GFS**, используя температуру и геопотенциальную высоту на изобарических уровнях. Если данных недостаточно — выводится отсутствие оценки, а не придуманная линия.
- Windy по-прежнему используется для **погодной карты**, штатного планировщика и публикации плагина. Ключ `WINDY_API_KEY`, если ранее требовался для GitHub Actions `publish-plugin`, остаётся необходимым **только для публикации плагина**.

## Установка через GitHub Codespaces (из корня репозитория)

Загрузить `Windy-Flight-Route-Analyzer-FULL-v0.10.2.zip` в корень репозитория через интерфейс Codespaces, затем выполнить:

```bash
unzip -o Windy-Flight-Route-Analyzer-FULL-v0.10.2.zip
# Удаляем устаревшие исходники платного Windy Point Forecast proxy из предыдущей версии:
rm -f src/windyWeather.ts api/windy-forecast.js tests/test_windy_proxy_v010.mjs
npm install --no-audit --no-fund
npm run test:release
```

`npm run test:release` последовательно выполняет проверки структуры, конфигурации сборки, импортов/экспортов, TypeScript, автоматические тесты, **настоящую сборку Rollup/Svelte** и проверку файлов `dist`. При любой ошибке **не публикуйте** и пришлите текст первой ошибки из терминала.

Если всё успешно:

```bash
git add -A -- . ':!*.zip' ':!*.sha256'
git status --short
git commit -m "Use automatic Open-Meteo GFS forecast without API keys v0.10.2"
git push origin main
```

Проверьте `git status` до коммита, чтобы в репозиторий не попали ключи или сторонние данные. Затем GitHub → **Actions → publish-plugin → Run workflow → main**. Для этого workflow нужен **только** ранее настроенный репозиторный секрет `WINDY_API_KEY` (ключ загрузки плагина в Windy), а не Point Forecast.

## Работа с таблицей

1. Откройте плагин Windy и вставьте маршрут OFP с распознанными точками.
2. Укажите ETD в UTC.
3. Нажмите **«Построить метеопрофиль и подобрать эшелоны»**. Никаких других ключей или URL вводить не нужно.
4. Результаты появятся на графике. Таблицы FL300–FL400: **Настройки → Прогноз и таблицы FL300–FL400**.
5. В настройках откройте **Источник прогноза: Open-Meteo GFS** для объяснения модели и условий лицензии.

Если увидите `Open-Meteo HTTP 429`, достигнут лимит бесплатного API — повторите позже. `HTTP 400` означает, что сервис отверг запрос; запишите сообщение целиком. Если ETA выходит за 16-дневный горизонт или не хватает параметров — приложение сообщает об этом, вместо заполнения таблицы вымышленными значениями. Если по маршруту есть неизвестные FIX или разрывы, сначала исправьте маршрут или загрузите корректную навигационную базу.

## Лицензия и ограничения

Безключевой Open-Meteo Free API допускается **только для некоммерческого использования** (не более 10 000 вызовов/день, 5 000/час, 600/минуту) и требует указания источника по CC BY 4.0. Для коммерческой эксплуатации требуется отдельное соглашение/план: https://open-meteo.com/en/terms

Таблица Open-Meteo GFS не тождественна значениям, визуально показанным выбранным слоем карты Windy (например ECMWF). Прогноз на изобарических уровнях, перерасчёт в FL, тропопауза, ISA и рекомендации по ветру **не предназначены для оперативного планирования или определения разрешённого эшелона**; не учитывают аэродинамику/массу/расход топлива/ограничения воздушного пространства/реальные трассы/поправку времени по ветру.

## Проверка доступности

При подключении к интернету в браузере можно проверить ответ поставщика, открыв официальный пример: https://api.open-meteo.com/v1/forecast?latitude=52.37&longitude=4.90&hourly=temperature_300hPa,wind_speed_300hPa&models=gfs_seamless&forecast_days=1

В этой среде подготовки проекта **не удалось выполнить реальный HTTP-запрос к Open-Meteo или установить пакеты npm из-за ошибки DNS**. Проверка на GitHub Codespaces обязательна перед публикацией; локальные тесты имитируют ответы API и проверяют разбор реальных по формату данных.
