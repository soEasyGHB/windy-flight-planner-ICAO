# Проверка Windy Flight Route Analyzer v0.9.5

База: полный исходный проект v0.9.4.

## Причины «нажал, но ничего не происходит»

1. `openWeatherProfile()` в v0.9.4 сначала ждал `analyze()`, и только после успешного запроса и `weather.length > 0` показывал SVG-панель. При ошибке не появлялось никакого окна.
2. `analyze()` делал ранний `return` при любом пропущенном FIX, разрыве или невалидном ETD, оставляя текст только в скрытом подразделе «Сообщения, ошибки и ограничения».
3. После вставки нового OFP обработчик мог прочитать неуспевший реактивно обновиться флаг `canExportRoute`, несмотря на уже разобранный новый маршрут.
4. HTTP/сетевая ошибка Open-Meteo оставалась в скрытом общем `status`, а длительный запрос ничем не отражался.

## Исправления

- Панель профиля открывается синхронно по нажатию и показывает состояние запроса, даже без метеоданных.
- Кнопки подменяют надпись на «Загружаю профиль…», есть прогресс, объяснение ошибки и повторная попытка.
- Проверка маршрута делается по `parsed`, а не по устаревшему реактивному флагу; после разбора нового OFP панель остаётся открытой.
- Подробности HTTP-ошибок Open-Meteo отображаются после безопасного ограничения длины, сетевые ошибки и тайм-аут 30 секунд различаются.
- Сохранены запрет ложного соединения неизвестных FIX, FL330–390, маршрутные компоненты ветра, GPX, ISA, линия тропопаузы и Google Drive → GitHub.

## Проверки

- Node/TypeScript: `npm run typecheck:core`, `npm test`.
- 10 импортируемых модулей / 28 именованных экспортов: `npm run check:imports`, `npm run check:exports`.
- Новый тест `tests/test_profile_feedback_v095.mjs` проверяет наличие состояний профиля и имитирует успешный прогноз, HTTP 400 и сетевой отказ.
- Полный `npm run build` требует Windy/Rollup SDK в Codespaces; без него окончательная совместимость Svelte/публикации не подтверждена.
